🎯 The Big Picture — What Does This App Do?

Imagine you have a super-smart assistant sitting on your computer. You can talk to it in text or voice, and it can do all sorts of things for you. It's like your own private ChatGPT, but running on your own machine, with extra superpowers.

The project is split into two halves:

  • Frontend (what you see in the browser) — built with React + Vite
  • Backend (the brain that does the thinking) — built with Python + FastAPI

What Can It Do?

You do this…The assistant does this…
Type "What's the weather today?"Searches the web using Serper and gives you a real, current answer
"Send email to john@gmail.com about the meeting"Drafts the email, shows a preview, sends it when you approve
Upload a PDF resumeReads it, summarizes it, can edit specific text inside it
"Create a PDF about machine learning"Writes a full document with sections & headings, generates a downloadable PDF
Speak into your microphoneConverts speech → text, generates reply, speaks it back to you
"What did I tell you yesterday about my project?"Searches long-term memory and recalls what you said

The generate_reply() Pipeline — Step by Step

This is the heart of the entire system. When you send any message, this is what happens:

1. 📝 User sends message ↓ 2. 🔄 Reset search/email flags ↓ 3. 📎 PDF attached? → Save to disk & memory ↓ 4. 🔍 CONTEXT RETRIEVAL: ├─ Get document context (uploaded PDFs in this session) ├─ Get recent conversation (last 4 turns) ├─ Get long-term memory (cross-session facts) └─ Get relevant memory (vector similarity search) ↓ 5. 🛤️ ROUTING: ├─ Pending email approval? → Send/discard email ├─ New email request? → Parse, draft, show preview ├─ PDF request? → Create/edit/summarize PDF └─ Normal chat → Pick model, optionally web search ↓ 6. 🤖 Call Groq AI model via Agno framework ↓ 7. 💾 Save exchange to memory (PostgreSQL + embedding) ↓ 8. 📊 10+ turns? → Summarize old turns to save space ↓ 9. 📤 Return reply to frontend

Email Approval Flow

When you say "send email to john@example.com saying hello", the agent doesn't send immediately:

  1. Parses your request: extracts to, subject, body, cc, bcc
  2. Uses AI to generate a professional subject & body if you only gave a brief instruction
  3. Shows preview: "Here is the email I prepared. Should I send it?"
  4. Waits for your approval ("send it") or rejection ("cancel")
  5. Only then sends via Gmail API
Section 06

💾 Memory System — How It Remembers

memory.py (~853 lines) gives the AI persistent memory — it remembers things across conversations, not just within one chat.

Three Types of Memory

TypeScopeWhat It StoresExample
conversationWithin a sessionEvery chat exchange"User asked about Python, Agent explained…"
documentWithin a sessionUploaded PDF content, chunked"Page 1 of resume.pdf: Name: John Doe…"
long_termAcross ALL sessionsUser preferences & facts"User prefers dark mode"

How Vector Search Works (The Magic)

The memory system doesn't just store text — it stores text AND a numerical representation of its meaning (an "embedding"). This lets it search by meaning, not just exact words.

✨ Example

You said: "I love playing cricket on weekends" → stored with its embedding

Later, you ask: "What are my hobbies?"

The system finds the cricket message because "hobbies" and "playing cricket" have similar meanings in vector space!

Key Memory Functions

FunctionWhat It Does
save_conversation()Saves a chat exchange with its embedding
get_recent_context()Gets the last 4 messages (short-term context)
get_relevant_context()Vector search — finds similar past messages
get_long_term_memory()Vector search across ALL sessions
save_document_memory()Chunks PDF text & stores each chunk with embedding
summarize_old_turns()After 10+ turns, summarizes oldest 5 into one entry
list_sessions()Returns all sessions for the sidebar
delete_session()Deletes all data for a session

Rolling Summary — Keeping Memory Manageable

After 10 raw conversation turns in a session:

  1. Take the oldest 5 messages
  2. Ask the AI to summarize them into 2–3 sentences
  3. Delete the original 5 messages
  4. Store the summary with its own embedding

This way, old conversations are remembered in compressed form.

Text Chunking — How Documents Are Stored

A long PDF is split into overlapping chunks of 1,000 characters (with 150 char overlap). This ensures vector search is accurate and nothing at chunk boundaries is lost.

🛡️ Graceful Degradation
Every memory function is wrapped in try/except. If PostgreSQL is down, functions return safe defaults ("", []) instead of crashing. You can still chat — you just won't have memory.
Section 07

🔢 Embeddings — Turning Words into Numbers

embedding.py is a small but critical file. It converts text into 768-dimensional vectors (lists of 768 numbers).

What Are Embeddings?

Imagine representing every sentence as a point in space. Similar meanings = close points. Different meanings = far apart.

"I love dogs"            → [0.23, -0.45, 0.67, 0.12, ...]  (768 numbers)
"I adore puppies"        → [0.25, -0.43, 0.65, 0.14, ...]  (very similar!)
"The stock market fell"  → [-0.56, 0.78, -0.12, 0.34, ...] (very different!)

The project uses sentence-transformers with the all-mpnet-base-v2 model. It runs locally — no internet needed.

🔄 Fallback
If sentence-transformers isn't installed, a hash-based fallback creates crude embeddings. Not as accurate, but the app won't crash.

Section 09

🎤 Voice — Speech ↔ Text

Speech → Text: whisper_service.py

A separate FastAPI server on port 8001 using Faster-Whisper (a fast C++ implementation of OpenAI's Whisper).

  • Model: large-v3-turbo (accurate but fast)
  • Runs on CPU with int8 quantization (no GPU needed)
  • Voice Activity Detection (VAD) enabled to skip silence
Browser records audio (WebM) ↓ POST /chat-voice-input → main.py ↓ Forwards audio to POST localhost:8001/transcribe ↓ Whisper model runs → returns transcript ↓ generate_reply(transcript) → AI response ↓ Piper TTS → synthesize(reply) → WAV audio bytes ↓ Return { transcript, reply, audio (base64) } ↓ Frontend plays audio + shows messages

Text → Speech: tts.py

Uses Piper, a local neural TTS engine. It runs Piper as a subprocess, pipes text in, and gets a WAV file out. The WAV bytes are base64-encoded and sent to the frontend which plays them.

Section 10

📧 Gmail Integration

OAuth Flow: gmail_auth.py

Handles the complex OAuth2 authentication with Google:

  1. User clicks "Connect Gmail" in the frontend
  2. Frontend calls GET /email/auth
  3. Backend starts a temporary local web server on a random port
  4. Returns a Google consent URL → user is redirected to Google login
  5. User grants permission for Gmail access
  6. Google redirects back to the temp server with an auth code
  7. Backend exchanges the code for an access token
  8. Token saved to backend/token.json
  9. All future Gmail calls use this token

📄 PDF System

PDF Creation Flow

When you say "Create a PDF about machine learning":

1. agent.py detects PDF create intent (regex match) ↓ 2. Is it long-form? (essay, 1500 words, etc.) ├─ YES: Generate outline (5-6 sections) via AI │ For each section, generate ~250 words via AI │ Combine all sections └─ NO: Generate full document via single AI call ↓ 3. pdf_tool.create_topic_pdf(topic, body) ↓ 4. Parse body into blocks (headings, paragraphs, bullets) ↓ 5. Render page by page: • A4 size, professional margins • Bold title + accent underline • Section headings with accent marks • Word-wrapped prose with inline bold • Auto-pagination when content overflows • Headers (title + page number) on continuation pages • "Virtual Assist" branded footer ↓ 6. Save to backend/storage/generated/ ↓ 7. Return download URL: http://localhost:8000/files/filename.pdf

PDF Find/Replace — How Style Is Preserved

When you say "Change 'John' to 'Jane'":

  1. Search all pages for the text "John"
  2. Find the original span — capture its font name, font size, and color
  3. Redact the old text (draw a white rectangle over it)
  4. Insert the new text at the exact same position with the same font/size/color
  5. If direct match fails, an LLM fallback reads the PDF text and finds the closest matching text

🗄️ Database

PostgreSQL + pgvector

Database: vpa_db   |   Connection: postgresql://postgres:postgres@localhost:5432/vpa_db

The conversations Table

There's only one table, but it serves multiple purposes via the memory_type column:

CREATE TABLE conversations (
    id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id    text NOT NULL,         -- Which session this belongs to
    role          text NOT NULL,         -- 'exchange', 'summary', 'document_chunk', 'fact'
    content       text NOT NULL,         -- The actual text content
    summary       text,                  -- Summary (only for summarized old turns)
    embedding     vector NOT NULL,       -- 768-dim vector embedding
    source        text,                  -- Origin: 'chat', 'pdf_upload', 'long_term'
    memory_type   text NOT NULL DEFAULT 'conversation',
    file_path     text,                  -- Path to associated file
    created_at    timestamptz NOT NULL DEFAULT now()
);

Vector Search Query

The <=> operator computes cosine distance between vectors:

-- Find the 4 most similar past conversations
SELECT content, 1 - (embedding <=> $1::vector) AS similarity
FROM conversations
WHERE session_id = $2 AND memory_type = 'conversation'
ORDER BY embedding <=> $1::vector
LIMIT 4
🔄 Auto-Migration
The _ensure_schema() function automatically creates tables, adds missing columns, creates indexes, and detects embedding dimension mismatches (truncates table if model changes).

🔄 End-to-End Message Flow

Let's trace exactly what happens when you type: "What's the latest news about AI?"

("latest" matches SEARCH_KEYWORDS) d) WEB SEARCH: • search_web("What's the latest news about AI?") • → Serper returns 5 Google results • web_search_called = true • Results injected into system prompt e) MODEL SELECTION: • pick_model() → llama_model (no code keywords) f) CALL AI via Agno: • System prompt = grounding rules + context + search results • User prompt = "What's the latest news about AI?" • → Groq returns: "Here's the latest AI news: ..." g) SAVE TO MEMORY: • Embed combined text → 768-dim vector • INSERT INTO conversations (session_id, content, embedding, ...) h) CHECK TURNS: • count_raw_turns("default") → 3 (under 10, no summary needed) 5. 🐍 Backend returns to frontend: { reply: "Here's the latest...", used_search: true, model: "Groq" } 6. ⚛️ Frontend (App.jsx): • Sets loading = false → hides typing indicator • Creates agent message bubble (left side) • Shows "Powered by web search" badge • Refreshes session list sidebar 7. 👤 You see the response! ✅
